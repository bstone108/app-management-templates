# Resilio Sync runbook

> **Guide, not a rule.** This is a reviewed template from the app-management-templates repo. Safety-review it before use, adapt it to the local machine, and follow local judgment where they disagree. It was trial-tested on one Linux instance (Resilio Sync 3.1.2); the v3 web API it relies on is undocumented, so re-check it against the installed version.
> Name map: `self-hosted-app-runbook-template` = [`apps/_generic/runbook.md`](../_generic/runbook.md); `app-persistence-method` = [`apps/_generic/persistence-method.md`](../_generic/persistence-method.md); `syncthing-runbook-template` = [`apps/syncthing/runbook.md`](../syncthing/runbook.md). `app-management-sanity-check`, `app-management-daily-check` and `app-management-getting-started` are the consuming bot's own skills (the validator they install is [`scripts/am-validate`](../../scripts/am-validate)).

Follow `self-hosted-app-runbook-template` and use the values from the Resilio instance record. Judgment first (see `app-management-sanity-check`). Fields used here: `binary_path`, `install_link` (optional symlink to the binary), `installed_version`, `pinned_version`, `launcher_backup_dir`, `start_command`, `self_serve_start`, `restore_helper`, `health_command`, `log_cap_command`, `config_dir` (holds `config.json`), `state_dir` (= `storage_path`), `durable_root`, `api_address` (loopback `host:port`, same as `webui.listen`), `login_user`, `login_secret_file`, `listening_port`, `data_folders` (`label`, `path`, `mode`, `consumers`), `symlinks`, `cold_copy_dir`, `cold_copy_essentials`, `cold_copy_max`, `cold_copy_refresh_command`, `cold_copy_full_refresh_command`, `log_path`, `allow_major_upgrade`, `depends_on`, `consumers`.
Web UI: `http://<api_address>/` (loopback only). The login is read from `login_secret_file` at runtime and never printed. If `self_serve_start: true`, any bot may run `start_command`; otherwise notify the app-management bot.

## Scripts (in this repo's `scripts/`; pin a commit and check sha256 against `index.json`; test in a throwaway directory first)
Every script takes the instance record path as its first argument (except `resilio-api`, see below), reads only the record keys it needs, never prints secrets, and manages only Resilio.
| Script | Does |
|---|---|
| `start-resilio <record>` | Starts Resilio fully detached (own session, fds closed, stdin `/dev/null`, `umask` from the record's `data_umask` (default 022; logs pre-created 600) so the log is mode 600), waits up to 30 s for the web UI. Exit 0 healthy (also at once if it already is), 1 not healthy or binary/config missing, 2 usage. Installs, upgrades and restores nothing. |
| `resilio-install <record>` | Installs the binary **only if missing**, through the signed chain below. Version: `RESILIO_VERSION`, else the record's `installed_version`, else the repo's newest. Never upgrades. |
| `resilio-restore <record> preflight` | The `restore_helper` for `restore-guard`. Durable-first: changes nothing when the live state is present and intact; otherwise falls back to the cold copy. |
| `snapshot-resilio-identity <record> [--with-db]` | Cold-copy refresh (light while running; `--with-db` = clean stop, full copy, verify, restart through `start_command`). |
| `resilio-access <record> [--check]` | Optional: gives one extra group (record `access_group`) access to the synced data folders through ACLs (see Data folder access). No `access_group` = does nothing. |
| `resilio-health <record>` | Non-secret health lines; exit 0 healthy, 1 not. |
| `resilio-logcap <record>` | Caps the log at ~1 MiB when it is over 5 MiB, in place, mode 600, no rotated copies, no restart. |
| `resilio-api [--record <record>] <command>` | Secret-safe web API helper (reads, safe writes, guarded risky writes, key/link/approval commands behind explicit flags). Config from the record (`RESILIO_RECORD` or `--record`). |
| `restore-guard` | The generic safeguards script. Resilio needs the version with the `restore_helper` record key and trailing-whitespace-safe comment stripping. |
Keep launcher copies in `launcher_backup_dir` with `SHA256SUMS` and verify before use.

## Install policy
- **Fresh install** (the owner's request is the approval): the newest stable **v3** Linux tarball from the vendor CDN, **verified through the signed apt repo but never installed with apt/dpkg** (the .deb adds system users and services). `resilio-install` does the chain: vendor key fingerprint pinned in the script, a good signature on `dists/<suite>/InRelease`, `Packages` hash listed in the signed `Release`, the .deb's SHA256 from `Packages`, the `rslsync` inside the extracted .deb byte-identical to the CDN tarball's `rslsync` (the tarball alone has no signature), and `rslsync --help` showing the expected version.
- **Never cross majors** (v2 and v3 differ in licensing, and mixed peers under one identity can conflict). For an existing install, report a higher major once, record `major_upgrade_offered`, and wait for approval. Minor/patch upgrades go unattended if the vendor changelog is harmless and the app is not pinned. A reinstall after a wipe uses the recorded `installed_version`, no approval.
- Keep the binary on durable storage with an `install_link` symlink in the user's bin dir; keep `rslsync.prev` on upgrade.

## Owner lifecycle (first run: a person or a browser step is required)
Never put share keys, licence, identity link or the login in chat, notes, logs or the registry. Sanity-check every config write.
1. **Install and start the launcher first** (config below). Do not try to create a login or accept anything by script: the web UI refuses API calls until the terms are accepted in the page.
2. **Terms:** accept in the web UI (a browser step).
3. **Login:** create the web login (one fixed username for the bot) with a strong random password. The password lives only in `login_secret_file` (mode 600, dir 700, outside synced folders) and is an **essential backup item**. The record holds only its path.
4. **Identity / licence:** on the first-run screen choose the small-text **"Manual connection"** option (instead of applying or acquiring a licence) and enter the owner's **identity link** (supplied through a secure form), then the owner approves the pairing request on their own device. The licence arrives with the identity; there is no key field to fill in. Confirm `getlicenseinfo` shows `valid` and `allowed_to_sync`, then refresh the cold copy.
5. **Default for new folders:** in settings choose **"Default connect folder mode: Disconnected"** (equivalent: `resilio-api set defaultsynclevel 0`). There is no config-file key for it, and the file-based per-share `selective_sync` needs `shared_folders`, which disables the web UI, so do not use it. Without this, every folder the owner adds later downloads in full onto the machine.
6. **Folders:** **default new folders to Advanced** (per-user permissions, no keys) **when the licence allows it** (`resilio-api add-folder <dir> --yes-add` picks Advanced if `getlicenseinfo` is valid and its `type` is not 0, and reports the type it actually got; otherwise it falls back to **Standard**, the classic key-based folder; say which one was used). Use Standard only when the owner asks for it or the licence does not allow Advanced. Read & Write or Read-only as the owner decides (prefer Read-only where a node must never push stale data). Do not create or share keys or links unless the owner asks. Record each in `data_folders` with `consumers` and its type. **One sync engine per path:** pause/stop any other sync app on that path first. The first scan can show the folder as upload-pending until a peer connects; that is normal. Then apply the default ignore list below.
7. **Removing a folder or peer, or wiping data:** a destructive ask (offer pausing instead). Folder data is deleted only with separate explicit approval.
8. **Consumers:** record which bots use which folder; after a verified fix send each a "restored, retry now" note naming folders and the outage window.

## Config (instance values come from the record)
JSON file passed with `--config` (`//` comments allowed). Keys used: `device_name`, `listening_port` (fixed, non-conflicting; TCP+UDP; it binds all interfaces and no bind option is used: say so in the record), `storage_path` (**always set**, otherwise Sync writes `.sync/` into the current directory), `pid_file` (non-durable), `use_upnp: false`, `send_statistics: false`, `check_for_updates: false` (never self-update), `folder_defaults.use_dht: false`, `folder_defaults.lan_discovery_mode`, `webui.listen: 127.0.0.1:<port>`. **No** `shared_folders` (disables the web UI and exposes keys in the file) and **no** login in the file (the UI creates it). Weak-device knobs (`worker_threads_count`, `folder_rescan_interval`, `rate_limit_*`) only when a measured need appears.

## Durable data
- `config_dir/config.json` (600). `state_dir` (700), the one important directory: `settings.dat` (+`.old`), `sync.dat` (folder list and state, written when folders exist and at clean shutdown), `.SyncUser<id>/` (identity.dat, licence record, paired devices, per-folder records), `License/<n>/` (licence.bin and key file, 600), the per-folder SQLite databases (`<id>.<n>.db`, `.files.db`, `.sf.db`, with `-wal`/`-shm`), `storage.db`, plus rebuildable runtime files (`sync.lng`, `http.port`, `FileDelayConfig`, `debug.txt`). Identity, licence and settings are SECRET.
- Per synced folder: `<folder>/.sync/` (`ID`, `IgnoreList`, `StreamsList`, `root_acl_entry`, `Archive/` holding 30-day versions of replaced or deleted files, temp `*.!sync` / `.bts`). **Never delete it, never sync it with another tool, and never back up `Archive/` or temp files.**
- **The databases are persisted exactly like Syncthing's index** (losing them can cause unwanted duplicates): live on durable storage via `storage_path`, plus one cold copy, at most two copies (a dedicated dir marked `.app-mgmt-cold-copy`, dirs 700, files 600, never inside a synced folder or `state_dir`). **Cold copy contents:** `config.json`, `settings.dat`, `sync.dat`, `.SyncUser*/`, `License/`, the login secret, every `*.db` with its `-wal`/`-shm`, and each synced folder's `.sync` metadata (`ID`, `IgnoreList`, `StreamsList`, `root_acl_entry`; the folder ID is tied to the databases) plus a list of folder paths. **Never** `Archive/`, temp files, logs, `*.old`, runtime files.
- The databases are **locked while Resilio runs**, so a copy of a live instance is not consistent. Take the database copy only after a **clean stop** (`SIGTERM`, wait for exit so the WAL is checkpointed and `sync.dat` is saved; never `kill -9`), copy, `cmp`, restart (`snapshot-resilio-identity --with-db`; a few seconds of downtime; the `.full-copy-ok` marker is removed at the start and written only after verification). The light refresh (no flag, safe while running) copies only the non-database essentials and leaves the last good database copy as it is. Do the light refresh after pairing, folder changes and each healthy daily check; do the full refresh after pairing/folder changes settle and then at most about weekly (skip while a large initial sync is running and say so).
- Never run an outside SQLite client against a live database; integrity checks use a temp copy.

## Persistence rule and the recovery order
**Primary = the live state on durable storage, reached by `--config` / `storage_path` and by symlinks from the standard places; the cold copy is only the fallback when the durable state is missing or damaged.** Record `symlinks` for the binary link, a home shortcut to the persist dir, and the packaged default location (for example `~/.config/resilio-sync` pointing at the persist dir) so a bare start can never create a second identity elsewhere. After every start confirm from `/proc/<pid>/fd` that the databases and binary are opened from the durable paths.
What a reset or upgrade typically wipes: the user bin dir (launchers and the binary link), the standard-location links, `/tmp` (log, pid, locks), sometimes the live state. What survives: the durable root (binary, config, state; the record, registry and launcher backups; the cold copy; the synced folders and their `.sync/`).
Recovery order (restore section of the base runbook with these Resilio specifics): validator → launchers from the backup dir (`sha256sum -c`) → `restore-guard <record> preflight` (delegates to `restore_helper`, because Resilio's state is not "flat identity files plus one DB dir": it **does nothing when durable state is present and intact**, checking SQLite `integrity_check` on temp copies; only when state is missing, partial or corrupt does it move it aside as `<path>.pre-restore-<ts>` and restore one consistent set from the cold copy, databases only from a copy marked `.full-copy-ok`; it exits 3 when state is missing everywhere: stop and ask) → `resilio-install` only if the binary is gone → `restore-guard <record> link <link> <target>` for every recorded symlink (relinks the surviving durable state) → `start_command` → verify (health; identity and licence files unchanged; same folder id and file count; no new `.sync/Archive` items or conflict copies) → `restore-guard <record> commit`. Roll back on failure. **Never delete databases or `.sync` for errors or stuck scans**: keep them, collect the log, report. Never create a new identity while a cold copy exists; if both live and cold state are missing, stop and ask.

## Rollback guard (not implemented)
Goal (same idea as the Syncthing runbook, only after a detected whole-disk snapshot restore; normal starts unchanged): detect that `state_dir`'s newest file mtime is far older than kernel boot. Resilio has no receive-only/revert button and no conflict copies (newest mtime wins; the loser goes to `.sync/Archive`), so a rolled-back machine could push stale files. An untested idea: hold the shares read-only until peers' newer content arrives, archive stale-only files to a recovery dir (two run dirs max), then restore the folder mode; on failure stay read-only and write a flag file. Until something like it exists, after a detected rollback: stop, do not start in Read & Write, tell the owner. Files restored from an external snapshot keep old mtimes and lose to peers' newer copies: touch them, or restore only files missing everywhere, on **one** node at a time.

## Health (scriptable, no browser, nothing accepted)
`resilio-health` checks: process by exact name `rslsync`; the web UI port listening on loopback; unauthenticated `GET /gui/token.html` → **401** (UI up and gated); few fatal-type lines in the log tail (the log is chatty, filter out `API:` lines, and it holds session tokens: keep it non-durable, mode 600, never paste it); then an authenticated pass (section "Web API") printing only non-secret fields: `getstatuses`, `version`, `pause` flag, `getlicenseinfo` validity, peers online, and per folder `files`, `local_files`, `local_size`, `error`, `paused`, `indexing`, `onlinepeerscount` and queue sizes. A response in an unexpected format is **"health unknown"**, not "down". Memory: tens of MB idle, growing while indexing. `onlinepeerscount` 0 is normal when no peer is online; report only if it stays 0 across checks while peers are expected.

## Web API (undocumented v3; observed on 3.1.2; use `resilio-api`)
- **Auth (all three needed on every call):** HTTP Basic header; `GET /gui/token.html?t=<ms>` returns the token in `<div id='token'>` and sets the `GUID_<hex>_<port>` session cookie; every call is `GET /gui/?action=<name>&token=<token>&t=<ms>&<params>` with Basic and the cookie. No expiry seen in minutes of use (a stale token gives 400 `invalid request`: fetch a new one and retry once). Cheapest: one cookie jar and one token per script run; 100 calls took ~2.6 s, no rate limit seen. Responses: `{"status":200,"value":…}`, `{"error":…,"status":500}`, or 400 `Unknown action`.
- **Cheap reads:** `getstatuses`, `getsyncfolders&discovery=1`, `getmfdevices` (peers), `getlicenseinfo`, `settings`, `advancedsettings`, `history&start=0&length=<n>` (no `order` parameter), `pause` (global flag), `version`, `getsessionstats`. `events` is a long poll (~30 s): never poll it. Many guessed names do not exist (`getsettings`, `getversion`, `getidentity`, …).
- **Secrets to filter:** `secret`, `readonlysecret` and `share_id` in the folder list (the folder's read-write and read-only keys), `owner_id`/`support_id`/`users` in licence info, device ids, MAC and IP addresses in the peer list, host and user names in system info, the token and cookie. `resilio-api` filters these.
- **Safe writes (tested):** `setpause&value=true|false` (**global**; a `folderid` is ignored), `rescanfolder&id=`, `setsettings&devicename=|defaultsynclevel=|dlrate=|ulrate=|debug_logging=` (read back to verify; `defaultsynclevel` 0 = new folders stay disconnected), `setadvancedsettings&<name>=<value>` (some need a restart), `setselectivesync&folderid=&selectivesync=true|false`, `setfolderpref&id=&transferpriority=&relay=&usetracker=&searchlan=&usehosts=`. Ignore patterns are the file `<folder>/.sync/IgnoreList` (edit, then rescan; no API call). `debug_logging=false` takes effect at once and cuts log volume (it is stored in `state_dir/debug.txt`, which is not a cold-copy item, so re-apply it after a state restore).
- **Risky writes (tested only on throwaway folders, never on a data folder):** `addsyncfolder&path=<existing dir>&selectivesync=false` creates an **Advanced** folder (no `secret` parameter; needs a licence that allows it; `ismanaged: true`), the same call with `&secret=` (empty) creates a **Standard** key-based folder; either is a new share that syncs to the identity's other devices. `removefolder&folderid=&deletedirectory=false&fromalldevices=true` removes it from every device of the identity (never use `deletedirectory=true`). `resilio-api` needs `--yes-add` / `--yes-remove` and refuses folders listed in the record's `data_folders`.
- **Keys, links and approvals (outside peers only):** Standard folders show `secret` (read-write, `A…`) and `readonlysecret` (read-only, `B…`) in `getsyncfolders` (33 uppercase base32 characters each); Advanced folders have no keys. `getsynclink&folderid=&permissions=2|3&timelimit=<s>&clicklimit=<n>&askapproval=0|1|2&type=copy&linktype=https` makes an invitation link for either type (2 = read-only, 3 = read-write; approval 0 none, 1 new peers, 2 every peer). An outside peer's request shows in `getpendingrequests`; the owner answers with `setrequeststatus&folderid=&fingerprint=&status=2|3|1` (untested against a real peer). `resilio-api keys|link|approvals|approve` wrap these, print keys and links to stdout only behind `--yes-show-key` / `--yes-link`, and never log them. With a shared identity none of this is needed.
- **Needs a person or the browser:** accepting the terms, creating the login, entering the identity link (`setmfsecret`), the owner's approval of the pairing on their device, licence registration, and connecting folders the owner offers (`getdisconnectedfolders`; do not connect without the owner's say-so). For an outside peer prefer the read-only permission and `askapproval`, and only when the owner asks.
- **Drift:** the API is the web UI's private API. After any version change re-run `resilio-api status/folders/peers/license` and `resilio-health`; a missing field, HTML instead of JSON or a new status code means "health unknown": report, do not guess. `Unknown action` = wrong or removed name; 401 = Basic credentials wrong or login not created; 400 `invalid request` = token or cookie problem.

## Data folder access (optional: record key `access_group`, default none)
Synced files are created by the Resilio user, so another account on the same machine (for example another agent's user) may be shut out by the default owner-only modes. Fix it durably with ACLs, not file-by-file chmods. Set `access_group: <group>` (and optionally `data_umask: 002`, default `022`, the daemon's umask) in the record, then run `resilio-access <record>`:
- It adds a named-group ACL (`rwX`) to everything in each `data_folders` path and a **default ACL** on directories, so files Resilio creates or syncs later inherit it. The default ACL's *other* entry copies the folder's existing other bits: a private folder stays private, a world-readable one is unchanged. Nothing is ever widened for anyone but the named group.
- `.sync/` internals are never touched. Directories above a data folder that the group cannot enter (for example a 700 home directory) get a traverse-only ACL (`g:<group>:--x`).
- Needs the distro `acl` package; the script installs it once through `sudo -n apt-get install -y acl` if missing (a package install does not survive a machine reset, so the daily check re-runs it). Without ACLs it falls back to `chgrp` + `g+rwX` + setgid directories and says so.
- `resilio-access <record> --check` reports only (exit 1 = entries without the ACL); the daily check runs `--check` and, on problems, re-applies (never per-file). The daemon umask only matters outside ACL directories; secret-bearing state (`resilio-persist`, storage, config, login) stays private (700/600), and `start-resilio` pre-creates its logs 600 and re-chmods the debug log after start (the daemon rewrites its mode).
- There is no documented Sync config key for file permissions on Linux (`posix_fs_acl`/`sync_extended_attributes` are undocumented and not relied on).

## Default ignore list (documented default for a synced folder)
Resilio's ignore list is the file `<folder>/.sync/IgnoreList` (UTF-8; `#` comments; one pattern per line; `*` and `?` wildcards; a bare name matches that file or directory at any depth). There is no API call for it: edit the file, then `resilio-api rescan <folder>` (verified: the new patterns take effect on the next rescan and already-synced ignored files drop out of the folder). New folders start with the vendor's own junk list (`Thumbs.db`, `desktop.ini`, `ehthumbs.db`, `$RECYCLE.BIN`, `System Volume Information`, `.DS_Store`, `._*`, `.Spotlight-V100`, `.Trashes`, `.fseventsd`, `.TemporaryItems`, `.DocumentRevisions-V100`, `.Trash-*`, `~*`, `*~`, `*.tmp`, `*.swp`, `*.part` and more). Append these extras (exact names or narrow wildcards, nothing that can match a real document), keeping the existing lines:
```
# macOS
.AppleDouble
.LSOverride
.VolumeIcon.icns
__MACOSX
# Linux
.directory
.nfs*
# Leftovers of a previously used sync engine (Syncthing)
.stfolder
.stignore
.stversions
*.syncthing.*.tmp
.syncthing.*
```
Not added on purpose: `*.lnk` (shortcuts can be real content), `Icon?` (would also match real five-letter names; macOS's `Icon\r` file is rarely seen). Verify any change with a throwaway file in a subdirectory (it must disappear from `getfileslist`/the file count while look-alike names such as `my.directory.pdf` stay), then delete the test file. Existing junk already in the folder is deleted by hand after listing it first (a list of exactly what matched, saved), never with a broader pattern than the ones above, and it syncs as a deletion to the other devices.

## Upgrade (daily check Update step; rules in base section 7)
Auto-update is off (`check_for_updates: false`). Latest = `Version:` in the signed apt `Packages` file; compare with the installed version (`resilio-api version`, or `rslsync --help` run from a scratch directory: see Pitfalls). Read the vendor changelog for every version in range (terse notes: judge harmless by same major, patch-level change, no storage/config-format or licence change); anything unclear → ask. Before: health OK, cold copy refreshed (`--with-db`). Then: stop with `SIGTERM` and wait for exit, move the binary to `rslsync.prev`, run `RESILIO_VERSION=<new> resilio-install <record>` (it installs only into the now-empty path, through the verification chain), start, run health, record the window and update `installed_version` and `binary_sha256`. Failure → put `.prev` back. Before any major, copy `state_dir` while stopped (replace the cold copy, do not add a third).

## Backups
At most two copies of anything per app (live + one cold). Logs, caches and `.sync/Archive` are not backed up; databases are (clean-stop copy only). Back up launchers with `SHA256SUMS`.

## Owner's rules (same as the other runbooks)
- **Launcher independence:** `start-resilio` starts only Resilio and never starts or chains another app. Cross-app recovery belongs to the daily check.
- **Silent recovery:** successful restarts, repairs and upgrades are silent; message the owner only when something needs a decision or action (approval, pairing, terms, repair failed, rollback flag). Tell consumer bots "restored, retry" after a verified fix.
- Launchers refuse unknown arguments (`--help` must never start the app in the caller's foreground) and exit 0 when already healthy.
- Secrets never in logs, registry, notes, skills or reports; refer to locations only.
- Judgment first, destructive actions ask, one sync engine per folder path.

## Pitfalls
- **Running `rslsync` without `--config`/`storage_path`, even just `--help`, creates a `.sync/` directory (settings, language file, log) in the current directory.** Run version checks from a scratch directory and delete it, never from a synced folder, the repo or the home directory. A stray `.sync/` inside a folder Resilio later syncs is read as that folder's metadata.
- The web UI and `shared_folders` in the config are mutually exclusive.
- `.sync` is internal: no other tool may sync it. If another engine (for example Syncthing) used the same path, pause it and, when the owner confirms, remove that folder from it; a leftover `.stfolder` is harmless to Resilio, but a resumed Syncthing would treat `.sync` as content unless ignored.
- Newest-mtime-wins; clock skew beyond `sync_max_time_diff` (600 s) stops transfers.
- The default new-folder mode is a UI setting, not a file key: re-check it after any identity re-pairing.
- Reverting the whole machine to an old snapshot reverts state and data together; see the rollback guard section.
- inotify watch limits (one per directory) delay change detection until the next rescan interval.
